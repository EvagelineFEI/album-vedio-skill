# 单页修改与视频片段复用

用于已经有工程的相册修改。页号从 1 开始，对应 `scenes` 的顺序；同组两张照片在左页时仍算一个页组。

## 编辑流程

1. 找到原 `project.json`、源素材和缓存。在原配置上修改目标页，沿用其他页的资产、文案、布局、时长，以及全书已选定的主题与配方。不要因为局部修改重新执行整本图片生成。
2. 先查看受影响页的关键帧，并执行 `--cache-plan`。这是只读计划，不生成 MP4、音轨或缓存。
3. 使用同一缓存导出新的 MP4。检查 `.render.json` 的 `rendered_segments`、`reused_segments` 和 `audio_reused`，据实际结果说明更新范围。
4. 检查新页及前后翻页、拼接接缝、声音同步；保留旧成片与新报告，保留缓存供后续使用。

标题与文案的问询仅用于信息尚未明确的新制作。改某页不重复问标题，也不丢开已经校对的稿件重写全书。

## 命令

```bash
python3 SKILL_DIR/scripts/render_book.py /project/project.json --cache-plan
python3 SKILL_DIR/scripts/render_book.py /project/project.json --output /project/album-v2.mp4
```

默认缓存目录为 `/project/.album-cache/project/`，根据配置文件位置与不含扩展名的文件名确定，和 MP4 的名字无关。可以显式固定：

```bash
python3 SKILL_DIR/scripts/render_book.py /project/project-v2.json --cache-dir /project/.album-cache/project --output /project/album-v2.mp4
```

自动修改检测通常无需指定页号。`--rebuild-pages 2,4` 强制刷新对应页面及邻接开书/翻页/结尾；它不限制自动检测，其他依赖确实变化时仍需更新。`--rebuild-all` 忽略已有缓存重做全部片段和音轨，并更新缓存。已有输出文件需换名，或明确使用 `--overwrite`。

## 更新范围

| 修改内容 | 视频片段 | 声音 |
| --- | --- | --- |
| 中间页的文字、布局、抠图，时长不变 | 该页与前后翻页 | 声音事件不变时复用 |
| 某页停留时长改变 | 该页及相邻翻页；后面的页面仍可复用 | 重排口播、翻页音效并重混连续配乐 |
| 更换口播或配乐，画面时长不变 | 所有画面可复用 | 更新连续音轨 |
| 第一页变化 | 该页、开书及后续翻页 | 按实际时间与声音变化处理 |
| 最后一页变化 | 该页、前一翻页及结尾 | 按实际时间与声音变化处理 |
| 仅修改片尾词 | 片尾；其他页面及片头可复用 | 片尾时长不变时可复用音轨 |
| 原照片同时用于封面或相机吐片 | 该页、相邻翻页，以及受影响的片头/开书 | 按实际事件变化处理 |
| 全局字体、主题、材质、开本、帧率或渲染环境改变 | 所有受影响的片段，可能是全片 | 必要时重混 |

自动取色或自动配方依赖照片与标题。首次制作完成后，把 `.timeline.json` 的 `resolved_theme` 作为配置的 `theme`，并把 `cover_recipe` 中的 A/B/C/D 与 seed 固定到配置，能让局部换照片保留原设计。若仍允许自动重新取色，照片变化导致整体色彩变化时，多个页面重做是正确行为。渲染器不会为了缓存命中而忽略主题修改。

## 实际实现与边界

- 独立生成静音的片头、开书、各页、翻页和结尾；使用相同编码参数，各段独立解码。最后通过 FFmpeg concat 和视频流复制拼接，复用部分不重新编码。配乐、快门、翻页音效与口播作为全片连续音轨统一混音、编码，避免每段 AAC 的填充和接缝。
- 按素材的实际文件内容、动画时序、字体、已解析的布局/纸面/背景，以及脚本和编码环境生成缓存键。原文件同名覆盖也能发现，文件名和修改时间不作为唯一依据。文字校对记录等不影响画面的元数据不会令所有页面失效。
- 所有段落使用统一的整数帧时间线和局部动画时间。前页延长后，下游页面只移动位置，不因为全片绝对时间变化重新采样动态图。时长向上取整到帧边界，实际值保存在时间表中。
- 每个缓存片段附有字节数和 SHA-256；缺失、未完成或校验不符会重新生成。中断后，已经完成并验证的片段仍可复用；没有自动删除其他版本的缓存。
- 音轨独立缓存。字幕/排版改变但时长和声音事件不变时可复用；口播、音乐、事件或时间表改变时重新混音，画面缓存不因此全部失效。
- 第一次导出或丢失缓存需要建立相应片段。只有旧 MP4、缺少原工程或素材时，不能承诺重建可编辑图层。此功能节省逐帧合成与视频编码；读取工程、检查素材、重混变化音轨及最终拼接仍需时间。

缓存留在个人工程，包含实际照片画面，不打包进公共 skill 仓库。需要换电脑继续修改时，将原工程、素材和缓存一起迁移；运行环境变化可能令旧缓存重新生成。

多文件夹使用同一个总工程和缓存。`--part <id>` 只渲染该部分的片段，最后通过总工程补上跨部分翻页；不按各部分分别建立独立视觉配方。参见 [collections-and-outro.md](collections-and-outro.md)。

技术依据：[FFmpeg concat demuxer](https://ffmpeg.org/ffmpeg-formats.html#concat)、[FFmpeg streamcopy](https://ffmpeg.org/ffmpeg.html#Streamcopy)。
