# 剪辑前询问、文案校对、同前缀分组与动态来源

这些规则用于开始制作新视频。只修改 skill、解释方法或检查配置时，不向用户追问本次视频的标题/文案/片尾词，也不自行生成样片。

## 开工前的选择

在剪辑、生成片头或素材之前，把缺失的选择一次问清楚：

1. “这本电子相册需要使用你指定的标题吗？可以直接给我标题，也可以让我根据图片拟定，或不加标题。”
2. “这次会提供文案吗？有的话请发原稿；没有的话，我会根据图片写简短、有生活感的配文。”
3. “片尾需要指定一句话吗？可以提供原句、让我代拟，或不加文字。”

片尾词的选择对整片只问一次，多个文件夹不各自询问。用户明确不加片尾时跳过这项；已经提供的片尾原句先检查明显错字，保留原意。记录为 `intake.ending={"mode":"user","value":"下次再见。"}`、已授权代拟的 assistant/value，或明确无词的 `{"mode":"none"}`。没有选择时，不能用默认告别语假装用户已授权。

用户在本轮或同一次制作中已经给出明确标题、稿件、片尾词，或已说明由助手代拟/不提供时，直接复用，不重复询问。只问尚不明确的项。等待必需答案期间可整理文件、检查格式和顺序，不提前决定用户尚未选择的标题或文本来源。

## 有文案：先校对，再按图分配

- 保留原稿；逐句检查错别字、重复字、漏字、标点、病句以及人名/地名/数字是否前后一致。
- 明确无歧义的错字、重复字和标点可轻校正并简要告知修改。专有名词、日期、数量、指代或可能改变含义的疑点先问清楚，不凭感觉“纠正”。不把校对变成擅自改写风格。
- 记录 `original`、`corrected`、`edits`。实际校对由 agent 完成；脚本不自动做中文纠错，不得仅写一个 checked 标记就声称审过稿。
- 先根据图片顺序和同前缀页组建立主题，再把校对后的文案按语义、画面和页组分段。既不能按字数平均切开，也不能不看图直接逐句分配。
- 多文件夹先建立一个全片提纲和一份完整校对稿，再分配到页组与部分；检查上一部分末页与下一部分首页是否承接，避免每部分重新开场或重复总结。相同的时间、地点、称谓与叙事视角保持一致，未知信息不补造。具体记录与分批合成见 [collections-and-outro.md](collections-and-outro.md)。
- 有稿时采用 `caption_policy=provided-script`。页面文字来自校对稿的对应片段，忠实保留含义与重要信息；不默认另写一套与原稿无关的诗句。上一版“有口播也独立另写配文”的默认在此条件下被覆盖。
- 用户明确区分“口播原稿”和“页面题记”，或授权摘录/改写时，按其选择分别保存；不要把用户已经指定的题记再改掉。
- 文案太长时先调整排版、字号与停留；无法保持可读性时询问是否允许摘录、增加文本页或让长内容留给口播，不静默删段、丢事实或缩到难以阅读。
- 没有文案时才用 `observational-poetry`，根据图片写简短生活观察。标题和文案都不用编造日期、关系、地点或经历。

`intake` 记录示例（仅数据格式，不代表已经问过当前用户）：

```json
{
  "title": {"mode": "user", "value": "秋日散步"},
  "ending": {"mode": "none"},
  "copy": {
    "mode": "provided",
    "original": "原始文案",
    "corrected": "校对后的文案",
    "edits": [{"before": "明显错字", "after": "正确用字", "reason": "错别字"}]
  }
}
```

`title.mode` 可为 user / assistant / none。none 表示无标题，封面保留装帧和照片，回书不播放空的书名动画。assistant 表示已授权代拟，制作前仍要把实际拟定标题写入工程。

## 连续同前缀图片：同一页组

在生成抠图与逐页文案之前、重命名拷贝之前先用原始文件名分组，保留用户给定的输入顺序。下载缓存或改名后的路径应同时保留 original_name，不能拿临时哈希名猜分组。可调用 `scripts/album_inputs.py` 生成分组计划；它只整理文件，不渲染媒体。

- `街角_01.jpg`、`街角_02.gif` → 同一页组，原图都排在左页，右页从整组画面选元素和分配文案。
- `街角-窗户-01.jpg`、`街角-树梢-02.jpg` → 可按显式语义前缀“街角”合组。
- `街角（1）.jpg`、`街角（2）.jpg` → 同组。
- “街角_01、河边_01、街角_02” → 三组；不能跨过中间图片把两个街角重排到一起。
- IMG / DSC / DSCF / PXL / default 等通用相机前缀、任意共同字母或年份，不当作事件语义前缀。不能把整个相机相册错误地合成一页。
- 用户显式分组或顺序优先；无可靠前缀时分别处理，不猜测事件关系。Live Photo 的静态文件与对应 motion_file 是一个来源，不当成两张照片。

同一组是同一幕/跨页中的左页组合。两张可根据横竖比例选择上下、并排或错落，三张以上建立大小主次或整洁网格；图不变形、重要主体不被遮挡。可使用 `photo_layout` 或自由 `photo_boxes` 调整，不要求一套宫格用于所有页。

保留组内所有图片。图片多到无法清楚展示时，先建议更大开本或征询是否拆页，不静默丢图、只挑一张，也不未经说明把同组拆开。

## 动态图片：保留原内容的运动

- GIF、APNG、动态 WebP 以多帧输入读取，保持画布、帧顺序、逐帧时长、透明度与帧合成/处置。不能用首帧保存为 JPEG 来代替动画。
- 页面里的照片、片头吐片和封面嵌图若采用动态来源，都应呈现该来源的真实多帧变化。单张静图的摆动或缩放不等于保留原动态。
- 页面/组件首次显示时开始播放，默认按原速度循环以覆盖停留时间；用户要求原循环次数时设置 `playback=source`，只播一次用 once。允许保留原动态的循环，不擅自加速以凑时长。
- 视频输出是逐帧合成：翻页、照片移动或书本变形时，照片画面仍由对应时刻的源帧供给。预览图片仅用于检查，不得把预览缓存回写成原始素材。
- Live Photo 有 JPEG/HEIC 与 MOV 配对时，在同一图片项使用 `motion_file`；嵌入式 Motion Photo 需要正确抽取动态段。缺少动态文件或解码器时说明缺口并索取完整来源，不悄悄降级为静态。
- 右页若使用真实透明多帧元素，保留其画布和时序，不逐帧抠框居中导致运动抖动。图像模型只做单帧重塑时，不能声称完成了动态抠图；原图运动应至少在照片区域完整保留。
- 原声与动态画面分开处理；是否保留原声、配乐或口播由声音要求决定，不能把“保留动态”当成已经制作口播。
